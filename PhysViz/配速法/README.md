|---|---|---|
| 首发模型 | 配速法（带电粒子在正交电磁场中的运动） | 第 7 章 |

## 1. 项目定位

### 1.1 定位

将高中物理中抽象、反直觉、课本静态插图无法有效表达的物理模型，转化为可实时调参、可自由旋转视角、可任意跳转时间轴的 3D 交互式实验台。

### 1.2 目标用户画像

**主要用户**：高中物理教师，使用投影仪或大屏进行课堂演示。

| 维度 | 特征 |
|---|---|
| 计算机素养 | 熟练使用 PPT，但对专业软件的参数面板和高级选项缺乏耐心 |
| 操作时间 | 课堂中随时调整，每次操作预算 < 5 秒 |
| 硬件环境 | 学校配发的集成显卡办公笔记本；投影仪分辨率可能低至 1024×768 |
| 网络条件 | 教室网络不稳定，离线可用为刚性需求 |
| 输入设备 | 键盘 + 翻页笔（方向键 / PageUp / PageDown） |
| 核心诉求 | 快速展示参数变化对物理结果的影响，而非“播放一段动画” |

学生端功能不在本项目的范围内。

### 1.3 非目标

以下功能明确不在本项目的设计与实现范围内：

- 题库管理与作业批改系统
- 学生账号体系与登录功能
- 后端服务与数据库
- AI 生成 3D 模型资产（所有几何体由代码程序化生成）
- 通用物理引擎式的“任意场景搭建”能力

### 1.4 设计原则

当设计决策出现冲突时，按以下优先级裁决：

1. **物理正确性** 优先于视觉表现。错误的矢量方向比不绘制矢量更严重。
2. **操作效率** 优先于功能丰富度。操作步骤超过三步的功能视为不可用。
3. **默认视图质量** 优先于可调自由度。首次打开即应具备教学演示能力，无需预先调整相机或参数。
4. **离线可用** 优先于在线功能。
5. **性能稳定性** 优先于画面质量。目标硬件为集成显卡环境，性能余量有限。

视觉风格参考科研论文图表的质感：图案简洁明确，配色可调整且具备学术规范性。


## 2. 使用场景与约束

### 2.1 课堂演示流程

教师打开平台后，通过预设例题库进入演示动画。侧边栏提供参数调整、色彩调整、时间轴控制（暂停、倒放、倍速、跳转至指定时间点/时间段）、播放速度设置、轨迹设定、画笔标注（支持图形模式与高亮模式）。参数面板中的各项参数（包括坐标轴位置等场景参数）均可实时调整。

### 2.2 硬约束

| 约束项 | 具体指标 | 对应的设计动作 |
|---|---|---|
| 投影分辨率 | 最低 1024×768 | 布局以 1024px 宽度为基准，关键控件不因响应式压缩而变形 |
| 最小可读字号 | 18px（投影后等效屏幕 14px） | 所有参数标签、读数不低于 18px |
| 最小线宽 | 2px | 轨迹线、矢量箭头线宽不低于 2px，投影环境下细线可能不可见 |
| 对比度 | 深色线条 + 浅色背景 | 避免浅灰描边与低饱和配色 |
| 网络条件 | 可能无网络连接 | 纯静态部署 + PWA 预缓存，首屏加载后完全离线可用 |
| GPU 能力 | 集成显卡 | 禁用阴影、后期处理、高精度反射 |
| 输入设备 | 鼠标 + 翻页笔 + 键盘 | 提供完整的键盘映射方案（见 8.5 节） |
| 操作步数 | 打开至开始讲解 ≤ 3 步 | 预设例题库置于首屏显著位置 |

### 2.3 关键推论

为教师提供两种使用路径：（1）从经典例题库进入，在预设参数基础上微调以适配具体教学场景；（2）自主配置全部参数，从空白场景开始构建演示。


## 3. 技术选型

| 层次 | 选型 | 决策依据 |
|---|---|---|
| 构建工具 | Vite | 毫秒级热更新，物理公式修改后可立即观察渲染效果 |
| 框架 | React 18 + TypeScript | 参数到视图的声明式映射与 React 的组件模型天然契合 |
| 3D 引擎 | three.js + @react-three/fiber + @react-three/drei | R3F 将场景转化为组件树，参数变化自动触发重渲染，无需手写命令式同步逻辑 |
| 状态管理 | Zustand | 轻量级方案，无 Provider 嵌套，支持 selector 精确订阅以避免不必要的重渲染 |
| 数学库 | three 内置 Vector3 / Quaternion | 满足矢量运算需求，无需引入 mathjs |
| 数值计算 | 自研解析解引擎（见 6.2 节） | 不引入通用物理引擎 |
| 测试框架 | Vitest | 物理公式必须通过单元测试验证 |
| 部署方式 | 静态托管 + vite-plugin-pwa | 满足离线可用需求 |

### 3.1 物理引擎选型说明

**不使用 cannon-es、rapier、matter.js 等通用物理引擎。** 原因如下：

此类引擎的核心能力在于刚体碰撞检测与约束求解。本项目处理的场景是已知力场中的运动——洛伦兹力 \(q\mathbf{v}\times\mathbf{B}\)、万有引力 \(-GMm\hat{r}/r^2\) 等——不存在碰撞与接触约束。使用此类引擎意味着：绕过其内置积分器、禁用碰撞检测、手动注入力，最终仅利用了其不到 5% 的功能，却引入了约 200KB 的体积开销。

更重要的是，此类引擎仅提供数值解。本项目的核心需求是时间轴可跳转至任意时刻、可倒放，而数值解无法满足此需求（除非重放完整历史记录）。

### 3.2 解析解优先原则

**系统状态必须表示为 \((params, t)\) 的纯函数，而非可变的累积状态。**

该原则决定了整个架构的设计方向：

| 需求 | 有状态方案（数值积分） | 无状态方案（解析解） |
|---|---|---|
| 时间轴跳转至第 3 秒 | 必须从头重算 | `sample(3.0)` 直接求值 |
| 倒放 | 需存储完整历史 | 负方向采样即可 |
| 参数修改后立即重算 | 必须重启模拟 | 更换参数后重新采样 |
| 长时间运行误差 | 存在累积漂移 | 零漂移 |

配速法、开普勒问题、圆锥摆、驻波均存在闭式解。RK4 数值积分仅作为未来的兜底方案，本期不实现。

### 4.2 数据流

数据流为单向、无回写：

```
用户调整参数
   ↓
store.params = next
   ↓
model.init(params)  →  Derived（v_d, ω_c, r, T, k 等派生量）
   ↓
model.sample(t)     →  State（位置、速度、加速度、时间）
   ↓
 ├─ model.vectors(state)  →  VectorSpec[]
 ├─ model.layers(state)   →  轨迹点集 / 投影 / 辅助线
 └─ model.readings(state) →  实时读数
   ↓
场景重建（React 重渲染）
```

关键约束：**没有任何一步是“修改上一步的结果”。** 所有输出均从 \((params, t)\) 重新推导。这是时间轴可任意跳转的根本原因。

### 5.2 接口收益分析

新增物理模型的工作量为：编写一个 `physics.ts`（物理公式）+ 一个 `model.ts`（模型实现）+ 在注册表中注册一行。

参数面板、时间轴、图层开关、矢量渲染、读数栏、预设按钮、URL 分享——全部通过接口自动获得，无需编写任何 UI 代码。该接口设计是项目可持续扩展的基础。


## 6. 仿真内核设计

### 6.1 单位系统

- 内部计算全部使用 SI 单位，不做隐式换算。
- 显示时自动添加 SI 前缀：`6.83e-9 m` → `6.83 nm`，`7.16e-11 s` → `71.6 ps`。
- 参数面板必须显示单位（教师需要在课堂上宣读）。

`src/core/units.ts` 实现 `formatSI(value, unit, digits)`，支持 p / n / μ / m / k / M 前缀。

### 6.2 虚拟时间控制器

**该设计解决的核心问题**：电子在 0.5 T 磁场中的回旋周期约为 71.6 ps。若按真实时间播放，视觉上无法观测到任何变化。

时间轴以周期为单位，而非秒：

```ts
interface TimeState {
  t: number            // 模型时间（秒，SI）
  speed: number        // 每秒推进的周期数
  playing: boolean
  direction: 1 | -1
}
```

- 播放模式：`t += dt_real × speed × period × direction`
- 时间轴拖动：`t = 目标周期数 × period`（直接赋值，不重放历史）
- 界面显示：主显示为“已过 2.5 个回旋周期”，辅显示为真实时间 `179 ps`

默认 `speed = 0.5`（即 2 秒完成一个周期），该节奏适合配合口头讲解。

### 6.3 尺度归一化

配速法的轨迹尺度为纳米级（默认参数下摆线拱高 13.6 nm），天体运动为 \(10^7\) m 级。同一引擎无法共用统一的世界坐标。

`src/core/scale.ts` 的职责：

1. 从 `model.layers()` 获取所有几何体的包围盒
2. 计算 `sceneScale = 目标屏幕尺寸 / 包围盒尺寸`
3. 渲染时统一乘以 `sceneScale`，**但所有读数和坐标标签显示真实物理值**

**尺度归一化属于渲染层职责，不侵入物理层。**

### 6.4 退化情况处理

以下退化情况必须显式处理，否则将产生 NaN 或 Infinity：

| 退化条件 | 处理方式 |
|---|---|
| `B → 0` | 配速法失效（\(v_d = E/B \to \infty\)）。参数滑块下限设为 0.02 T 并在 UI 中说明；若用户输入 0，退化为匀加速直线运动特判 |
| `E = 0` | \(v_d = 0\)，退化为纯匀速圆周运动，公式自然成立，无需特判 |
| `v' = 0` | 轨迹退化为直线，\(r = 0\)，跳过圆周项以避免除零 |
| `q = 0` | 粒子不受力，匀速直线运动，直接特判 |


## 7. 配速法模型详细设计

> 本章为实现的核心里程碑，所有公式均以可直接翻译为代码的形式给出。

### 7.1 物理原理

**设定**：匀强电场 \(\mathbf{E}\) 与匀强磁场 \(\mathbf{B}\) 正交（\(\mathbf{E}\perp\mathbf{B}\)）。带电粒子电荷量 \(q\)、质量 \(m\)，初速度 \(\mathbf{v}_0\)。

**运动方程**：

\[
m\frac{d\mathbf{v}}{dt} = q\left(\mathbf{E} + \mathbf{v}\times\mathbf{B}\right)
\]

**第一步——配速**。定义漂移速度：

\[
\mathbf{v}_d = \frac{\mathbf{E}\times\mathbf{B}}{B^2}
\]

验证其抵消电场力：

\[
\mathbf{v}_d\times\mathbf{B} = \frac{1}{B^2}\left[(\mathbf{E}\times\mathbf{B})\times\mathbf{B}\right] = \frac{1}{B^2}\left[\mathbf{B}(\mathbf{E}\cdot\mathbf{B}) - \mathbf{E}B^2\right]
\]

因 \(\mathbf{E}\perp\mathbf{B}\)，故 \(\mathbf{E}\cdot\mathbf{B}=0\)：

\[
\mathbf{v}_d\times\mathbf{B} = -\mathbf{E} \quad\Longrightarrow\quad q\left(\mathbf{E} + \mathbf{v}_d\times\mathbf{B}\right) = 0 \quad\checkmark
\]

**第二步——换系**。令 \(\mathbf{v} = \mathbf{v}_d + \mathbf{v}'\)，代入运动方程：

\[
m\frac{d\mathbf{v}'}{dt} = q\left(\mathbf{E} + \mathbf{v}_d\times\mathbf{B} + \mathbf{v}'\times\mathbf{B}\right) = q\,\mathbf{v}'\times\mathbf{B}
\]

电场项被消除，运动简化为匀强磁场中的匀速圆周运动。

**第三步——叠加**。实验室参考系中的轨迹为匀速漂移与匀速圆周运动的叠加，即**摆线族**。

### 7.2 派生量

| 物理量 | 公式 | 说明 |
|---|---|---|
| 漂移速度大小 | \(v_d = E/B\) | 方向沿 \(\mathbf{E}\times\mathbf{B}\) |
| 圆周分量 | \(v' = \lvert\mathbf{v}_0 - \mathbf{v}_d\rvert\) | 换系后的速度大小，恒定 |
| 回旋角频率 | \(\omega_c = \lvert q\rvert B/m\) | |
| 回旋半径 | \(r = v'/\omega_c = mv'/(\lvert q\rvert B)\) | |
| 回旋周期 | \(T = 2\pi/\omega_c = 2\pi m/(\lvert q\rvert B)\) | 与速度无关 |
| 摆线参数 | \(k = v'/v_d\) | 决定轨迹形状 |
| 最大速率 | \(v_{\max} = v' + v_d\) | |
| 最小速率 | \(v_{\min} = \lvert v' - v_d\rvert\) | \(k=1\) 时为 0 |

### 7.3 轨迹形状判据

| \(k = v'/v_d\) | 轨迹类型 | 特征 |
|---|---|---|
| \(k = 0\) | 直线 | 无圆周分量，纯匀速漂移 |
| \(0 < k < 1\) | 短幅摆线 | 波浪形，不回头 |
| \(k = 1\) | **标准摆线** | 出现**尖点**，尖点处速率为 0 |
| \(k > 1\) | 长幅摆线 | 出现**套环**（轨迹自交） |

\(k\) 可通过两个途径改变：调整 \(\mathbf{v}_0\)（改变 \(v'\)）或调整 \(E/B\)（改变 \(v_d\)）。**两个途径均需提供参数接口，对应两条不同的教学路径。**

### 7.4 解析解实现

约定：\(\mathbf{B} = B\hat{z}\)，\(\mathbf{v}_d\) 沿 \(+\hat{x}\) 方向，\(u = v_d = E/B\)。

设 \(\mathbf{v}'_0 = \mathbf{v}_0 - \mathbf{v}_d\)，将其分解为垂直分量 \(\mathbf{v}'_\perp\)（在 \(xy\) 平面内）与平行分量 \(\mathbf{v}'_\parallel\)（沿 \(z\) 轴）。

**位置解**：

\[
\begin{aligned}
x(t) &= x_0 + u\,t + r\left[\sin(\omega_c t + \varphi) - \sin\varphi\right] \\
y(t) &= y_0 + r\left[\cos(\omega_c t + \varphi) - \cos\varphi\right] \\
z(t) &= z_0 + v'_\parallel\,t
\end{aligned}
\]

其中 \(r = v'_\perp/\omega_c\)，\(\varphi\) 由 \(\mathbf{v}'_\perp\) 的初始方向确定。

**\(v_0 = 0\) 特例**（课本标准场景，默认预设）：

\[
x(t) = u\,t - r\sin(\omega_c t),\qquad y(t) = r\left[1 - \cos(\omega_c t)\right]
\]

验证：\(t=0\) 时 \(\dot{x} = u - r\omega_c = u - v' = 0\)，\(\dot{y} = 0\)，初速为零成立；\(t = 2\pi/\omega_c\) 时同样为零，轨迹出现尖点。

### 7.5 参数表

| key | 显示名 | 符号 | 单位 | 类型 | 默认值 | 范围 | 刻度 |
|---|---|---|---|---|---|---|---|
| `particle` | 粒子 | — | — | enum | `electron` | 电子 / 质子 / α粒子 | — |
| `E` | 电场强度 | E | V/m | number | 300 | 0 – 5000 | 线性 |
| `B` | 磁感应强度 | B | T | number | 0.5 | 0.02 – 2 | 对数 |
| `v0` | 初速度大小 | v₀ | m/s | number | 0 | 0 – 2×10⁷ | 对数（0 特判） |
| `theta` | 初速度与 B 夹角 | θ | ° | angle | 90 | 0 – 180 | 线性 |
| `phi` | 垂直面内方位角 | φ | ° | angle | 0 | 0 – 360 | 线性 |

**设计决策——以粒子下拉框替代 q、m 滑块**：目标用户不会操作数量级为 \(10^{-19}\) 的数值滑块，且误操作将直接导致物理结果错误。下拉框仅提供三个课本中出现的粒子：

```ts
const PARTICLES = {
  electron: { label: '电子', q: -1.602e-19, m: 9.109e-31 },
  proton:   { label: '质子', q:  1.602e-19, m: 1.673e-27 },
  alpha:    { label: 'α 粒子', q: 3.204e-19, m: 6.645e-27 },
}
```

**设计决策——θ 的教学价值**：默认值 90°（纯平面摆线，课本标准情况）。当 θ 偏离 90° 时，轨迹变为三维螺旋摆线。该现象无法在 2D 中正确表示，是 3D 演示必要性的直接证明。

### 7.6 矢量定义

| 矢量 | 颜色 | 图层 | 说明 |
|---|---|---|---|
| \(\mathbf{v}\) | `#0F6E56` 深绿 | `v` | 合速度，沿轨迹切线方向 |
| \(\mathbf{v}_d\) | `#185FA5` 深蓝 | `v` | 漂移分量，恒定不变 |
| \(\mathbf{v}'\) | `#534AB7` 深紫 | `v` | 圆周分量，大小恒定、方向旋转 |
| \(\mathbf{F} = q\mathbf{v}\times\mathbf{B}\) | `#A32D2D` 深红 | `F` | 洛伦兹力，始终垂直于 \(\mathbf{v}\) |
| \(q\mathbf{E}\) | `#BA7517` 深橙 | `F` | 电场力，恒定 |
| \(\mathbf{a}\) | `#993556` 深粉 | `a` | 加速度，默认关闭 |

**教学要点**：合力 \(\mathbf{F}_{net} = q\mathbf{v}'\times\mathbf{B}\) 的大小恒为 \(qv'B\)，方向始终垂直于 \(\mathbf{v}'\)，即圆周运动的向心力。虽然电场力和洛伦兹力各自随时间变化，但合力的**大小恒定**。该现象适合通过独立的“高亮”按钮在动画中展示。

### 7.10 验收用例（单元测试）

```ts
// 1. 初速为零 → 尖点处速率必须为 0
sample(t = n*T).v === 0  // 误差 < 1e-9

// 2. 长程平均漂移速度 = v_d
(r(t = 100T) - r(0)) / (100T) ≈ (E/B, 0, 0)   // 误差 < 1e-6

// 3. k = 0（v₀ = v_d）→ 轨迹为直线，r = 0
r === 0，位置共线（叉积 < 1e-12）

// 4. 周期与速度无关
改变 v₀ 大小（保持 θ 不变），T 保持不变

// 5. 能量守恒（电场力做功 = 动能变化）
½m|v(t)|² - ½m|v₀|² === qE · Δy(t)

// 6. 数值安全
B = 0 时不产生 NaN / Infinity，退化为匀加速运动

// 7. θ = 0（v₀ ∥ B）→ 沿 B 匀速，垂直面内仍为摆线
z(t) = v₀·t（沿 B 匀速，无加速度）；垂直面内 v′ = −v_d，
仍是标准摆线（k = 1）。轨迹不是一条平行于 z 的直线
```

**测试 5 的验证价值最高**：它同时验证了力的计算、积分正确性、符号约定。该测试通过即表示物理实现的正确性得到充分保证。

## 8. 渲染与交互设计

### 8.1 场景元素

| 元素 | 实现方案 |
|---|---|
| 粒子 | 球体，半径随场景尺度自适应（约屏幕 6px） |
| 轨迹 | drei 的 `<Line>` 组件。原生 `LineBasicMaterial` 的 `linewidth` 在多数平台无效，必须使用 `Line2` 以支持粗线宽 |

| 坐标轴 | 带真实单位刻度的 `Grid` + 自定义轴标签（使用 `troika-text` 或 drei 的 `<Text>`） |

### 8.2 相机策略

| 预设名称 | 内容 | 用途 |
|---|---|---|
| **正交俯视**（默认） | 正交投影，沿 −z 方向 | 平面场景的最优视角，视觉效果接近课本插图 |
| 透视自由 | 透视投影，OrbitControls | 用户自主旋转 |
| 侧视 | 沿 −y 方向 | 观察螺旋的侧影 |

**默认相机必须为正交俯视。** 透视投影会使摆线产生视觉畸变，降低学生对轨迹形状的辨识。3D 能力应在需要时释放（例如调整 θ 参数时）。

### 8.3 大屏/投影适配

- 所有线宽 ≥ 2px；轨迹线宽 3px
- 轨迹使用深色配色（`#185FA5` 级别），避免浅色
- 参数面板字号 ≥ 18px，读数 ≥ 20px

- 背景使用纯色浅底（`#FFFFFF` 或 `#F7F8FA`），不使用深色背景（投影仪黑色表现力有限，深色背景可能糊成一片）

### 8.4 图层开关面板

九个图层的开关需完整可见且不占用主视野。建议布局：右侧窄栏，图标 + 文字标签组合。

### 8.6 性能预算

| 指标项 | 目标值 |
|---|---|
| 首屏加载 | < 2s（离线缓存后 < 0.5s） |
| 帧率 | 集成显卡 60fps，最低不低于 30fps |
| 轨迹点数 | 500–5000 自适应；拖动滑块时降级到 500，拖动结束后补全 |
| 拖滑块重算延迟 | < 16ms（必须在单帧内完成，否则产生拖滞感） |
| 包体积 | < 1.5 MB（gzip 后） |

拖拽滑块时的重算必须在单帧内完成。若 2000 点采样超时，降级至 500 点，拖动结束后补全。这是实现“实时联动”手感的关键。

## 10. 教学编排层（POE）

### 10.1 设计依据

无教学引导的 3D 演示仅为动画展示，学生的认知参与度有限。**预测 → 观察 → 解释（Predict-Observe-Explain）** 是本项目的教学骨架：

```
① 展示问题（面板文字）
   「将 B 加倍，轨迹会如何变化？请先预测，不要操作。」
   ↓ 等待约 30 秒，让学生表达预测
② 点击「揭晓」→ 参数动画过渡到目标值 → 轨迹实时重算
   ↓
③ 展示解释（面板文字）
   「T = 2πm/(qB)，B 加倍 → T 减半 → 拱距减半」
```

### 10.2 数据结构

```ts
interface GuidedStep {
  question: string
  params: Record<string, number | string>
  explanation: string
  highlight?: string[]
}
```

每个预设例题关联一组 `GuidedStep[]`，教师通过 `→` 键逐步推进。

该层是 PhysViz 与通用物理动画工具的核心差异所在。动画制作本身不具备教学价值，将“预测—观察—解释”的教学节奏嵌入产品交互流程，才是教学工具的本质特征。

## 12. 风险与待确认问题

### 12.1 技术风险

| 风险项 | 描述 | 缓解措施 |
|---|---|---|
| 解析解泛化性 | 并非所有目标模型都有闭式解 | 预留 RK4 通道作为兜底方案 |
| 集显性能 | 集成显卡在复杂场景下可能无法维持 60fps | 预留降级策略：降低轨迹点数、关闭场标记 |
| 对比分屏的尺度一致 | 两模型使用不同 sceneScale 将导致视觉对比失真 | 统一使用基准模型的包围盒计算 sceneScale |

### 12.2 待确认问题

1. **项目名称**：暂定「悟理 PhysViz」，是否有其他偏好？
2. **双语支持**：当前设计为纯中文界面，是否需要英文版本？
3. **对比分屏实现**：“左右分屏同时运行”与“同一场景叠加两条不同颜色的轨迹”各有优势。前者更直观，后者更能展示差异细节。建议均实现，但需确认优先级。
4. **移动端适配**：教师场景为桌面大屏，但学生课后可能通过手机访问分享链接，是否需要适配？
5. **LLM 参数解析**：自然语言到参数 JSON 的转换能力是否为预期功能？该功能属于 M3+ 范围，需先确认 M1/M2 进度。


## 附录 A：实现顺序建议

**避免先构建通用框架。** 推荐实现顺序：

1. 以最简方式实现：单个 `App.tsx`，硬编码电子 + E + B，绘制一条摆线，验证视角旋转
2. 添加 B 参数滑块，观察轨迹重算——验证“实时联动”的技术可行性
3. 添加时间轴——验证“解析解可任意跳转”的架构设计
4. 上述两步验证通过后，再抽象 `PhysicsModel` 接口
5. 最后实现参数面板泛化、图层系统、预设库

**先抽象后实现是此类项目最常见的失败模式。** 为想象中的“第二个模型”设计过度复杂的接口，会在实现第一个模型时受到接口约束的阻碍。
