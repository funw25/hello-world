# 写给呆子的项目介绍
> 最终还是把这个贴上来了（应该没人会看吧）  
> Windows 软件 + 硬件模块 组成的模块化合成器。

## 整个项目系统是什么样子：
```text
Windows 电脑
└─ 上位机软件
   ├─ 钢琴卷帘界面
   ├─ 多通道音序编辑
   ├─ 保存/打开工程
   ├─ 播放控制
   └─ 串口通信
        │ 串口线（USB 转串口）
        ▼
硬件板子
└─ CH32V 单片机（队长）
   ├─ 收串口命令
   ├─ 控制发声
   └─ 可能自己播放音序
        ▼
合成器硬件
└─ OSC、DAC、滤波、电源、PCB
   └─ 多个合成器模块/乐器
```

电脑上的软件：画乐谱  
硬件：乐器  
串口线：连接软件和硬件的电话线通道  
单片机mcu：硬件上面的小型电脑，负责接收软件命令，控制硬件发声  

## 那些名词：
音序器：用来记录、编辑、储存并按顺序自动播放音乐资料（如音高、节奏、持续时间与力度等）的装置或软件。  

通道：一个通道对应一个合成器模块或乐器  

BPM：速度，比如 120 BPM 就是每分钟 120 拍。  

拍号：比如 4/4，表示每小节 4 拍。 

串口：电脑和单片机之间的通信方式，像电话线，双方必须约定“消息格式”（写出来是电脑能理解的，不是人类语言）

## 呆子提出的问题：
1.播放计时难题：三个方案，pc端实时计时/pc发一整段，mcu收到之后一直播放（ram不够用，我们要做的是专业人士级别的合成器）/分阶段，pc发一段，隔一会再发一段（团队未确认——ok，fine，我们各自发散不用确认）  
answer：做第三个方案，但前面两个保留思路，未来做备胎  

2.关于PC数据流的理解：
PC数据流：Project(工程) -> Channel(通道) -> Note(音符) -> 播放事件(NOTE_ON / NOTE_OFF) -> DebugOutput / SerialOutput(输出层)  
```text
Project
   │ 包含
   ▼
Channel
   │ 包含
   ▼
Note（音高、开始位置、持续时间）
   │ 播放引擎换算时间、排序
   ▼
播放事件（NOTE_ON / NOTE_OFF）
   │
   ├──> DebugOutput  -> 界面日志
   └──> SerialOutput -> 串口 -> MCU
```
