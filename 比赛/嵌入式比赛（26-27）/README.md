## 1. 项目背景

- 项目方向：基于 CH32V 系列 MCU 的模块化合成器系统。
- 参赛方向：嵌入式芯片与系统设计竞赛创意赛道。
- 团队目标：完成项目，提高作品质量。

## 2. 系统方案

### 2.1 总体架构

```text
PC 上位机（音序编辑、播放调度、串口发送）
        │  串口，CH340
        ▼
振荡器模块（接收音符事件、产生波形）
        │
        ▼
DAC 与模拟输出
```

### 2.2 职责边界

| 职责 | 归属 |
|---|---|
| 音序编辑、工程保存、播放计时与排序 | PC |
| 接收音符事件即发声，不负责计时与排序 | 硬件 |
| 波形生成、包络、DAC 输出 | 硬件 |
| 音高到频率的对应关系 | 硬件判断，PC 只发编号 |

依据：2026-10-11 确认 PC 充当触发器。详见 `每日进展.md` 2026-10-11。

### 2.3 软件分层

```text
用户界面层（ui/）
├─ main_window.py       菜单、通道面板、播放控制、BPM 与网格、事件日志、串口面板
├─ piano_roll.py        钢琴卷帘视图：网格、音符编辑、播放头
└─ app.py               程序入口
        │
        ▼
业务逻辑层（core/）
├─ playback.py          事件展平与排序、PlaybackEngine
└─ timing.py            网格整数与节拍、秒的换算
        │
        ▼
核心数据层（model/）
├─ project.py           Project：BPM、拍号、网格步进、通道集合
├─ channel.py           Channel：编号、名称、颜色、音符集合
└─ note.py              Note：音高、开始位置、持续时间
        │
        ▼
输出适配层（output/）
├─ base.py              接口
├─ debug_output.py      写事件日志
└─ serial_output.py     发串口
```

实际调用链为「界面层 → 业务逻辑层 → 输出适配层」，业务逻辑层读写核心数据层。业务逻辑层不依赖 PySide6，无图形环境也可测试。

关键：音序编辑器不直接操作串口。播放引擎产生统一的音符事件，由输出适配层处理。

代码细节与逐模块说明见 `sequencer/README.md`。

## 3. 功能需求

### 3.1 已确认

- 最终程序供普通 Windows 用户直接运行，计划打包为 `.exe`。
- 核心功能是多通道音序编辑器。一个通道对应一个合成器模块或乐器。
- 音高 `1～63`，`0` 表示休止或无音。频率映射由硬件确定。
- 横轴为以节拍为基础的离散时间网格，网格步进可调。
- 工程包含 BPM 与拍号。
- 音符包含音高、开始位置与持续时间。
- 支持点击或拖动创建音符。
- 数据结构允许同一通道内的音符重叠。
- 播放时必须能获得「哪个通道、哪个音高、何时开始、何时停止」。
- 工程可保存与重新打开，恢复通道、音符与时间设置。
- 当前不需要力度、音量与其他模块参数。
- 使用串口通信。

### 3.2 硬件约束

- 通道数上限为 2。
- 每个通道同一时刻只发一个音，不支持复音。PC 侧允许重叠，重叠时的硬件行为待确认。
- 音高标识由硬件在最后加入。

### 3.3 已完成

- 多通道音序编辑、钢琴卷帘、播放与暂停与停止、事件日志输出、工程 JSON 存取。
- 串口发送：端口扫描与选择、波特率选择、打开与关闭、发测试音。
- 测试 106 项通过，编译检查通过。

## 4. 已确定的技术信息

| 项 | 结论 |
|---|---|
| 串口芯片 | CH340 |
| 串口参数 | 115200、8 数据位、无校验，波特率做成可配置 |
| 端口选择 | 程序启动时扫描，列出可用 COM 口，手动选择 |
| 播放计时与排序 | PC 承担 |
| 脱机播放 | 暂不考虑 |
| 通道数 | 2 |
| 复音 | 每通道同一时刻一个音 |
| 音高 | `1～63` 有效，`0` 为休止 |
| 硬件音序表 | 不需要，PC 不做整段下发 |

#### 软件框架
```text
UI 界面层
├─ 主窗口、菜单和工程操作
├─ 通道面板
├─ 音序编辑画布
├─ 播放与时间设置栏
└─ 事件日志

业务逻辑层
├─ 工程控制
├─ 音符编辑与重叠检查
├─ BPM/tick 时间换算
└─ PC 播放调度

数据层
├─ Project
├─ Channel
├─ Note
└─ NoteEvent

输出层
├─ DebugOutput：第一阶段使用
└─ SerialOutput：串口协议确定后接入
```
音序画布不直接操作串口。播放调度生成统一事件，再交给调试输出或串口输出模块。首阶段可以不连接硬件，后续协议变化尽量限制在串口适配模块。

#### 编辑窗口初稿

- 顶部：文件、编辑、播放菜单，以及工程名称和保存状态。
- 左侧：通道列表，支持添加、删除、重命名和切换通道。
- 中央：音序画布，横轴为小节/拍，纵轴为音高编号 `1～63`。
- 下方：播放、暂停、停止、BPM、拍号、网格步进和播放位置。
- 底部：事件日志，显示时间、事件类型、通道和音高。

初步操作规则：
- 单击空网格创建默认网格长度的音符。
- 拖动音符主体可移动音符。
- 拖动音符右边缘可调整持续时间。
- 选中音符后按 Delete 删除。
- 编辑后吸附到当前网格。
- 同一通道的音符不可重叠；建议遇到冲突时拒绝操作并提示，不自动覆盖已有音符。该交互规则仍待确认。
- 不同通道允许在相同时间演奏。

#### 工程与播放数据

使用 JSON 内容，扩展名采用 `.mseq`。音符位置以整数 tick 保存，而非毫秒；修改 BPM 后，音符仍保持在原来的节拍位置。

```json
{
  "format_version": 1,
  "project_name": "新工程",
  "tempo_bpm": 120,
  "time_signature": {
    "numerator": 4,
    "denominator": 4
  },
  "ticks_per_beat": 480,
  "grid_ticks": 120,
  "channels": [
    {
      "id": "channel-1",
      "name": "通道 1",
      "hardware_channel": 1,
      "notes": [
        {
          "id": "note-1",
          "pitch_id": 32,
          "start_tick": 0,
          "duration_tick": 480
        }
      ]
    }
  ]
}
```

`480 ticks/拍` 是初步建议，实施前可再验证。工程格式版本用于识别当前文件结构，不代表承诺兼容旧格式。

内部播放事件包含：

- 事件类型：`NOTE_ON` 或 `NOTE_OFF`；
- 通道编号；
- 音高编号；
- 计划播放时间或 tick。

时间换算：

```text
目标秒数 = tick / ticks_per_beat × 60 / BPM
```

#### 开发阶段

1. **界面原型**：明确窗口布局和音符操作规则。
2. **编辑版本**：实现通道、音符、网格吸附和单音重叠检查。
3. **播放模拟**：实现播放头、时间换算和事件日志。
4. **工程存储**：实现工程保存、读取和基本数据校验。
5. **串口联调**：共同确定消息格式、波特率和 MCU 应答，再接入 `SerialOutput`。
6. **交付完善**：测试目标 Windows 环境并打包可运行程序。
