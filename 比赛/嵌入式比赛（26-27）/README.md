## 4. 已确认的软件需求

- 最终程序应供普通Windows用户直接运行，计划打包为.exe。
- 核心功能是多通道音序编辑器。
- 一个通道对应一个合成器模块或乐器。
- 通道数量不固定。
- 音高暂定为1～63，具体频率映射由硬件部分确定。
- `0` 表示休止或无音。
- 横轴采用以节拍为基础的离散时间网格。
- 网格步进可以调节。
- 工程需要 BPM 和拍号。
- 支持点击或拖动创建音符。
- 音符包含音高、开始位置和持续时间。
- 软件数据结构允许同一通道中的音符重叠，但硬件实际复音能力尚未确认。
- 播放时必须能够获得“哪个通道、哪个音高、何时开始、何时停止”。
- 在串口通信完成前，先把播放事件输出到界面侧栏日志。
- 工程需要保存和重新打开，并恢复通道、音符和时间设置。
- 不需要力度、音量和其他模块参数。
- 已确定使用串口通信，具体通信格式待硬件开发阶段共同确定。

## 9. 已学习概念

### 协议版本

协议版本是数据规则的编号，用于让发送方和接收方知道应该按照哪套格式解释数据。它不同于上位机软件版本和硬件型号。

目前建议：

- 工程文件保留 `format_version: 1`，但暂时不实现复杂的旧版本兼容。
- 串口通信协议在开始设计时称为 V1 草案；是否把版本号放入每条消息，留到通信设计阶段确定。

#### 软件框架

UI 界面层
├─ 主窗口、菜单和工程操作
├─ 通道面板
├─ 音序编辑画布
├─ 播放与时间设置栏
└─ 事件日志

业务逻辑层
├─ 工程控制
├─ 音符编辑与重叠检查

数据层
├─ Project
├─ Channel
├─ Note

输出层
├─ DebugOutput：第一阶段使用
└─ SerialOutput：串口协议确定后接入

音序画布不直接操作串口。播放调度生成统一事件，再交给调试输出或串口输出模块。首阶段可以不连接硬件，后续协议变化尽量限制在串口适配模块。

#### 编辑窗口初稿

- 顶部：文件、编辑、播放菜单，以及工程名称和保存状态。
- 左侧：通道列表，支持添加、删除、重命名和切换通道。
- 中央：音序画布，横轴为小节/拍，纵轴为音高编号 `1～63`。
- 下方：播放、暂停、停止、BPM、拍号、网格步进和播放位置。
- 底部：事件日志，显示时间、事件类型、通道和音高。

初步操作规则：
- 单击空网格创建默认网格长度的音符。
- 拖动音符主体可移动音符。
- 拖动音符右边缘可调整持续时间。
- 选中音符后按 Delete 删除。
- 编辑后吸附到当前网格。
- 同一通道的音符不可重叠；建议遇到冲突时拒绝操作并提示，不自动覆盖已有音符。该交互规则仍待确认。
- 不同通道允许在相同时间演奏。

### 工程与播放数据

使用 JSON 内容，扩展名采用 `.mseq`。音符位置以整数 tick 保存，而非毫秒；修改 BPM 后，音符仍保持在原来的节拍位置。

```json
{
  "format_version": 1,
  "project_name": "新工程",
  "tempo_bpm": 120,
  "time_signature": {
    "numerator": 4,
    "denominator": 4
  },
  "ticks_per_beat": 480,
  "grid_ticks": 120,
  "channels": [
    {
      "id": "channel-1",
      "name": "通道 1",
      "hardware_channel": 1,
      "notes": [
        {
          "id": "note-1",
          "pitch_id": 32,
          "start_tick": 0,
          "duration_tick": 480
        }
      ]
    }
  ]
}
```

`480 ticks/拍` 是初步建议，实施前可再验证。工程格式版本用于识别当前文件结构，不代表承诺兼容旧格式。

内部播放事件包含：

- 事件类型：`NOTE_ON` 或 `NOTE_OFF`；
- 通道编号；
- 音高编号；
- 计划播放时间或 tick。

时间换算：

```text
目标秒数 = tick / ticks_per_beat × 60 / BPM
```
