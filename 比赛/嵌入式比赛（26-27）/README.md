## 4. 已确认的软件需求

- 最终程序应供普通Windows用户直接运行，计划打包为.exe。
- 核心功能是多通道音序编辑器。
- 一个通道对应一个合成器模块或乐器。
- 通道数量不固定。
- 音高暂定为1～63，具体频率映射由硬件部分确定。
- `0` 表示休止或无音。
- 横轴采用以节拍为基础的离散时间网格。
- 网格步进可以调节。
- 工程需要 BPM 和拍号。
- 支持点击或拖动创建音符。
- 音符包含音高、开始位置和持续时间。
- 软件数据结构允许同一通道中的音符重叠，但硬件实际复音能力尚未确认。
- 播放时必须能够获得“哪个通道、哪个音高、何时开始、何时停止”。
- 在串口通信完成前，先把播放事件输出到界面侧栏日志。
- 工程需要保存和重新打开，并恢复通道、音符和时间设置。
- 不需要力度、音量和其他模块参数。
- 已确定使用串口通信，具体通信格式待硬件开发阶段共同确定。

## 6. 初步软件架构

状态：总体方向已得到队长认可，内部细节仍可调整。

```text
用户界面
├─ 工程操作
├─ 通道列表
├─ 音序编辑器
├─ 播放控制
└─ 事件日志
       │
       ▼
业务逻辑
├─ 工程管理
├─ 音符编辑
├─ 时间换算
└─ 播放调度
       │
       ▼
核心数据
├─ Project
├─ Channel
└─ Note
       │
       ▼
输出层
├─ DebugOutput
└─ SerialOutput
```

关键原则：音序编辑器不直接操作串口。播放引擎产生统一音符事件，再由调试输出或串口输出模块处理。

## 9. 已学习概念

### 协议版本

协议版本是数据规则的编号，用于让发送方和接收方知道应该按照哪套格式解释数据。它不同于上位机软件版本和硬件型号。

目前建议：

- 工程文件保留 `format_version: 1`，但暂时不实现复杂的旧版本兼容。
- 串口通信协议在开始设计时称为 V1 草案；是否把版本号放入每条消息，留到通信设计阶段确定。
